# 能力、请求时限与文件生命周期

本说明对应 `/app` 工作区的前端请求恢复合同。它不改变后端鉴权、所有权、
转换资源限制、任务计次、文件保留期或已有任务的 `expires_at`。

## 请求、转换与文件保留分别计时

| 时钟 | 当前边界 | 到时后的含义 |
| --- | --- | --- |
| 普通 API 请求 | 30 秒，包含响应头及整个 JSON 响应体 | 前端停止等待并提供恢复入口；服务端操作结果可能仍未确认 |
| 批量上传接收入队 | 180 秒，包含上传、前置校验、响应头及 JSON 响应体 | 原始提交仍可能已接收；保留同一批文件、引擎和幂等键供用户核对或安全重放 |
| ZIP 结果传输 | 180 秒，包含响应头及整个 blob 响应体 | 允许较慢的大批量结果传输；超时不自动重试或触发迟到下载 |
| 转换执行 | 普通 MarkItDown 45 秒；Docling 60 秒 | 后端单次转换运行边界，包含独立预览；不作为上传 HTTP 请求的时限 |
| 文件有效期 | 入队时记录到任务的 `expires_at` | 原文件和结果超过有效期即不可正常读取或下载；不同于请求超时 |

请求时限从请求开始计算，不在收到响应头后重置。除成功的 JSON 响应外，
错误响应的 JSON 读取和 ZIP blob 读取也受各自请求的完整时限约束。浏览器暂停页面
时计时回调可能延后；这不是服务端执行或物理删除的硬实时保证。

180 秒是前端等待预算，不是后端接收 SLA。依据现有实现：

- `state.py` 限制每批最多 10 文件、50 MiB
- `engines.py` 的 `validate_engine_uploads()` 对 Docling 文件逐一前置校验，
  每次 `preflight` 受 `PREFLIGHT_SECONDS = 8` 限制；10 文件校验可累计约 80 秒
- `app.py` 完成读取和前置校验后接收入队；实际转换异步运行
- `jobs.py` 的 ZIP 最多包含 10 份 Markdown，每份最多 2 MiB；20 MiB 量级
  的较慢传输使用与上传相同的 180 秒预算，不套用普通读取的 30 秒限制
- `deployment/nginx.conf.example` 的 `proxy_read_timeout 90s`、
  `proxy_send_timeout 90s` 和 `client_body_timeout 30s` 是独立的代理等待边界，
  可能比前端更早结束请求；本变更没有调整代理配置或安全边界

## 请求失败与明确取消

前端通过完整操作与截止计时器竞争，不能只依赖 `AbortController.abort()`。
即使传输或响应体读取没有响应 abort，工作区也能结束忙碌状态。
超时有独立的 `RequestTimeout` 错误，不会作为用户主动取消而静默丢弃。

切换结果、退出登录和 `pagehide` 引起的主动取消继续保持静默。每个 await
之后、任何账户或界面状态更新之前仍检查 epoch/取消/超时状态。已超时或已
取消的请求，后续无论成功、失败、401 或返回其他账户身份，都不能恢复旧
内容或清空新账户。完成、失败、超时及取消会释放计时器和 abort 监听器。

超时后不自动重发登录、注册、创建邀请、设置修改、上传或任务变更等操作。
现有只读状态刷新仍可运行。用户应先核对服务状态；超时不是“服务端未执行”
的证明。普通网络错误和身份不匹配的保护保持不变。已登录请求收到有效的 401
响应头时立即清空私有状态，不等待可能悬挂的错误正文；超时后才到达的旧
401 响应仍先经过时效检查，不能清空当前账户。未登录的启动/登录请求不
采用该私有状态重置分支。

## 上传结果未确认

上传超时后冻结当前提交的文件对象、顺序、引擎和 Idempotency-Key。
用户可刷新记录或点击安全重试，由后端幂等记录返回同一提交结果。
后续重放即使收到 403、429 或 5xx，也不能据此否认最早一次请求已接收，
因此继续保留同一身份。只有确认接收结果或用户明确放弃后才结束该意图；
明确放弃有既有二次计次风险提示。

本变更不增加自动上传重试，不修改服务端幂等/额度规则，不把请求超时
当成取消转换，也不会把已有任务改用其他引擎。

## 退出登录

点击退出立即清空页面中的原文件选择、结果、历史和账户私有状态，再等待
服务端确认。确认请求同样有 30 秒完整操作时限，包括成功响应的 JSON 读取。
失败或超时后可重试退出，但在退出确认前仍阻止新登录。

403 或身份不匹配继续使用既有跨页面账户切换处理：保持内容清空，要求重新
连接确认当前账户。迟到的旧退出响应不能改变之后登录的账户。

## 保留期与能力显示

保留时长只接受有限、严格大于零的 number；缺失、null、空串、数字字符串、
布尔值、零、负数和非有限值显示“由服务决定”。有效的小于 0.005 小时的
数值显示“不足 0.01 小时”，避免四舍五入成零。正常服务配置仍为 1 小时–7 天。

此显示校验不会替服务端补造有效期，不修改任务的绝对到期时间。重试和取消
均不延长已有任务到期时间。文件到期与历史元数据保留分别计算；显式删除不
等于擦除下载副本、备份或日志。详细合同见 [工作区说明](../packages/markitdown-web/README.md)
和 [备份与恢复](BACKUP-RESTORE.md)。

引擎是否可用继续由已读取的服务能力决定：不可用 Docling 不能通过改动 DOM
强制提交；不会静默切换引擎。此变更未新增引擎或降低能力失败时的拒绝边界。

## 验证范围

`node packages/markitdown-web/tests/frontend_dom.cjs` 的 94 个 DOM/状态场景包含
原有 69 个场景，以及悬挂响应头/成功和错误 JSON/ZIP blob、401 响应头立即清空私有内容、完整时限、ZIP 超过 30 秒仍继续且 180 秒到期、真实
AbortError、迟到成功/失败/401/跨账户响应、上传重放身份、退出隐私、非幂等
操作不自动重发、主动取消静默、计时器与监听器清理、严格保留期显示。

新增用例在修改前的 `app.js` 上可重现忙碌状态无法恢复等失败，修改后通过。
这些是可控时钟和传输替身下的状态回归，不替代真实浏览器、原生包验收、
精确发布提交的 CI、真实 Docling 或目标部署的网络/代理验收。
