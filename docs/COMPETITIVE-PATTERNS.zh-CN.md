# 文档转换桌面端与下载网站交互研究

研究日期：2026 年 10 月 7 日。对象：Gloamere 的 MarkItDown Electron 客户端与 Python 转换服务。

## 建议先做什么

先把一次转换的完整链路做可靠：用户知道文件发往哪里、哪些能力可用、失败后怎样继续、结果来自哪次转换、导出后能否独立使用。建议顺序是连接与能力检查、可恢复的批量队列、可信的结果与导出、真实可下载的发布页，最后加入快捷键与轻量反馈。

这份研究核查了七个产品的官方公开资料，未安装并实测这些产品。下文“已核实”指官方文档或页面明确记载；“设计建议”是结合项目条件提出的判断，不代表已获得用户研究或市场验证。产品文档会变化，引用版本与页面以本次访问为准。

项目边界来自当前任务背景，尚未在本研究中独立审计代码：已有邀请、认证、配额、队列、历史、预览、源码、对比、Markdown/ZIP manifest、管理设置；Docling 服务只在 Linux 可用。不能据此宣传 OCR、结构化 JSON 导出、全部离线或无损转换。manifest 是导出清单，不等于结构化文档 JSON。既有 Mac Developer ID 构建已签名，公证按要求暂停；本研究不执行签名、公证或发布。

## 七个产品的可迁移模式

### 1 CloudConvert：任务阶段和可追溯重试

已核实：Jobs 文档把典型流程拆为导入、转换、导出任务，提供异步状态、时间与引擎信息，并建议长任务不要阻塞应用等待。Tasks 文档支持取消 waiting/processing 任务；重试创建新 ID，模型提供 retry_of_task_id。官方安全页分别解释处理区域、隔离、存储、传输和访问控制。

设计建议：借鉴任务语义而非照搬界面。将“上传中”“排队中”“转换中”“生成导出包”分开呈现；重试保留原尝试并建立关联。取消、清除历史和删除服务端文件是不同操作。安全说明应描述本项目已实现的事实，不能复制其认证或隔离承诺。

注意：安全页称处理后删除文件，API 文档另称结束的任务在 24 小时后删除；不要将文件生命周期和任务记录生命周期视作同一件事，更不要套用其时间承诺。

来源：[Jobs](https://cloudconvert.com/docs/api-reference/jobs)、[Tasks](https://cloudconvert.com/docs/api-reference/tasks)、[Security](https://cloudconvert.com/security)

### 2 HandBrake：批量队列与输出名防冲突

已核实：可以逐项加入队列，也可以一次加入多个任务。官方队列指南明确要求唯一输出名，避免任务彼此覆盖；队列中可以移除和编辑任务。下载说明提供系统要求、官方来源、校验和，以及稳定版本与开发快照的区分。

设计建议：导入后先给出可检查的文件列表、预定输出名和目标位置；允许移除不需要的文件。相同文件名出现在不同目录时自动生成安全的新名字，并让用户看到映射。不要把“有队列”误认为已有中断恢复或运行中暂停能力，这些需单独验证。

来源：[Using the Queue](https://handbrake.fr/docs/en/latest/advanced/queue.html)、[Downloading and installing](https://handbrake.fr/docs/en/latest/get-handbrake/download-and-install.html)

### 3 Obsidian：让 Markdown 和附件真正可带走

已核实：Markdown 是其主要笔记格式；官方导入流程接受文件、文件夹与 ZIP，提供输出选项及示例预览。附件是可以通过文件系统访问的普通文件，可设置放置目录。下载页集中列出平台和包类型，并标出社区维护的 Flatpak。

设计建议：将“可迁移的结果”作为转换交付标准：Markdown 使用包内相对路径；保留附件目录；ZIP 解压后可被常见 Markdown 工具打开。展示“导出 Markdown”与“导出完整 ZIP”的区别。不能因为输出扩展名是 .md 就暗示所有下游应用兼容。

来源：[Import Markdown](https://obsidian.md/help/import/markdown)、[Attachments](https://obsidian.md/help/attachments)、[Downloads](https://obsidian.md/download)

### 4 LocalSend：一眼说清文件流向和下一步

已核实：官网用安装、选择文件、选择设备解释流程；明确其局域网传输模式、无需账号，以及默认 Downloads 保存位置。下载页提供各平台选择。这些隐私描述属于 LocalSend 自身的架构承诺。

设计建议：客户端常驻显示“处理服务：本机 / 服务器名称”，首次上传前说清数据会发往哪个已配置服务；完成后直接显示保存位置。C/S 客户端不应照搬“文件不会离开设备”或“完全离线”。对本机地址也要检查实际转换依赖，不能只看 localhost 就断言无外发。

来源：[Homepage and FAQ](https://localsend.org/)、[Downloads](https://localsend.org/download)

### 5 Raycast：键盘操作可发现且与当前对象相关

已核实：官方快捷键页列出方向键列表导航、Enter 主操作、Cmd/Ctrl+K 操作面板、Esc 返回，以及打开、显示文件位置等通用对象操作；动作面板可按名称搜索。

设计建议：先给队列与结果列表增加稳定的焦点和快捷键提示，再考虑命令面板。选中文件后只列出当前合法的动作。键盘优先不等于已经通过无障碍审计，屏幕阅读器、焦点顺序和状态播报需要单独测试。

来源：[Keyboard Shortcuts](https://manual.raycast.com/keyboard-shortcuts)

### 6 Zotero：文件名、展示名与重复项不能混为一谈

已核实：官方文件重命名文档区分附件标题与磁盘文件名，支持基于元数据命名；重复检测将项目标为可能重复并提供合并，合并保留集合及标签。其重复判断依赖书目元数据，不是通用文件字节去重方案。

设计建议：保留原始文件名、输出文件名、展示标题三者的明确关系。重复导入先提示“可能已转换”，让用户选择查看已有结果或重新转换；不要仅凭同名阻止新任务。若采用 hash 去重，把转换引擎、版本和配置纳入判断条件。

来源：[File Renaming](https://www.zotero.org/support/file_renaming)、[Duplicate Detection](https://www.zotero.org/support/duplicate_detection)

### 7 Pandoc：支持格式要有方向和边界

已核实：官网用方向区分输入、输出与双向格式。入门说明解释显式输入/输出格式、根据扩展名推断格式，以及部分输出需要额外依赖。Pandoc 是命令行工具，官方入门页明确没有 GUI。

设计建议：本项目的支持表应写成“输入格式 → Markdown”，并列出实际引擎条件及已知限制。只暴露当前服务真实支持的选择，不能把底层项目的全部格式或可选能力都当作已交付功能。错误扩展名和伪装文件需要服务器校验。

来源：[Format directions](https://pandoc.org/index.html)、[Getting started](https://www.pandoc.org/getting-started.html)

## 按优先级实施与验收

下面均为本项目建议，不是上述产品的功能声明。P0 表示核心链路或发布信任前提；P1 表示核心链路稳定后的效率改进；P2 表示小而有用的完善。

### P0 连接就绪与能力检查

页面区分服务连接、登录状态和可用转换能力；用户能理解“服务在线但登录过期”与“服务不可达”的差别。填写服务器地址后提供明确测试结果，成功后才允许提交。Docling 的条件来自服务端能力，而非客户端运行系统猜测。

验收：分别模拟 DNS/网络失败、超时、401、403、版本不兼容、Docling 不可用；每一种给出不同的下一步；没有可用能力时不接受提交。重新登录后待提交文件列表仍保留。显示的处理位置来自当前有效配置；敏感令牌不进入截图、日志或错误文本。

### P0 批量导入预检

拖拽和文件选择器进入同一预检逻辑。列表展示原名、大小、支持情况、预定输出名、可移除操作。文件夹递归若未实现，应明确说明，不能静默忽略。配额不足应在提交前提示，实际扣额仍由服务端原子确认。

验收：混合拖入有效文件、不支持格式、零字节文件、同名不同目录文件及重复文件；有效项仍可继续，问题逐项解释。超出服务返回的大小/数量/配额阈值时不能误报成功。先测试同一目录和 ZIP 内的大小写冲突、中文、空格、超长文件名及路径穿越名，禁止覆盖或逃逸。

### P0 可恢复队列与真实进度

把服务端状态映射为有限、可解释的用户状态；百分比只用于真实可计量阶段，无真实进度的转换阶段用文字、已用时间和不确定进度。取消先显示“正在取消”，收到服务端确认才变为“已取消”。

验收：上传断网、转换时客户端退出、重连、取消与完成竞争、连续点击重试。客户端恢复后按服务端 job ID 对账，不重复提交或重复扣额；取消后已完成的结果按真实状态展示。只重试失败项，成功项不重跑。若后端不支持取消或恢复，界面明确限制，不能用前端隐藏行冒充取消。

### P0 结果来源与导出完整性

结果面板包含预览、Markdown 源码、已有对比功能和简洁来源卡。来源卡建议记录原文件名、任务 ID、时间、引擎与版本、配置摘要、警告；数据尚未捕获时诚实显示未知。结果文件为空或警告存在时仍让用户看见，不用统一“成功”掩盖质量问题。

验收：用包含图片、表格、链接、Unicode 的固定样本验证预览和下载；解压 ZIP 后相对链接可解析，manifest 中每项对应实际文件；部分失败时明确成功/失败数量并可导出成功项。导出包不含本机绝对路径、令牌或不必要的服务器细节。空文本输出提示检查扫描件或内容限制，不声称已做 OCR。

### P0 文件隐私说明与安全预览

在提交前展示简短数据流向说明，详情页区分源文件、转换结果、任务历史的保存和删除行为。只有后端已有并可验证的保留期限才能写具体天数。预览 Markdown 需防止脚本、危险协议及不经用户选择的外部资源加载。

验收：恶意 HTML、javascript 链接、远程跟踪图片和异常文件名样本不产生脚本执行、不泄漏认证、不触发意外外网请求。清理历史和删除服务端文件的作用范围有不同说明。诊断导出经测试不含 token、文件内容或非必要个人路径，用户先预览再选择分享。

### P0 下载页面对应真实发布物

首屏说明产品做什么、需要哪类服务和账号、主要输入与输出；主下载按钮附平台，旁边有“其他平台”。下载区列出版本、架构、包类型、日期、最低系统要求、更新说明和校验和。平台检测只能建议，必须可手动覆盖。

验收：每个可点击下载项映射到真实存在的对应版本产物；尚未发布的平台显示“暂未提供”，不使用假链接。移动端可查看桌面下载信息而不误导安装。页面不声称未验证的签名、公证或自动更新状态；签名暂停期间保留真实状态说明。校验和从发布产物生成，不能以校验和替代发布者身份验证。

### P1 键盘与无障碍

先支持 Tab/Shift+Tab、方向键列表导航、Enter 打开结果、Esc 关闭对话框、Cmd/Ctrl+O 添加文件；动作旁显示适用于平台的快捷键。所有拖拽操作都能用文件选择器完成。

验收：只用键盘完成登录、导入、移除、提交、查看结果和导出；弹窗关闭后焦点回到原触发点；状态不只依赖颜色；屏幕阅读器能识别行名、状态和动作，完成播报不夺取焦点。200% 缩放不挡住主要操作；减少动态效果设置有效。

### P1 小而实际的效率改进

- 完成条显示“7 个已完成，1 个需处理”，把“查看失败项”做成直接动作
- 复制 Markdown 后按钮短暂改为“已复制”，不弹阻挡式对话框
- 显示输出位置并提供“在文件管理器中显示”，动作必须指向实际已保存文件
- 同名冲突提前预览新名称；保留原文件与输出文件对应关系
- 记住上次目录和面板宽度，但更换账号/服务器后不要误用另一身份的历史上下文
- 历史列表默认保留用户当前滚动和选择，后台刷新不跳回顶部

验收：大量文件完成时合并通知，不逐项轰炸；复制确认不改变剪贴板内容；长文件名仍可查看完整名称；刷新、切换预览和导出不会导致选择错位。

### P2 克制的愉悦细节

空状态提供一个不涉及隐私的小示例文件，让用户试出完整路径；用已完成数量反馈进展，不用虚构节省时间；完成时采用轻量状态变化，并尊重系统减少动态效果。可选“完成后通知”应由用户开启，成功动画不可延迟导出按钮出现。

## 官网页面建议顺序

1. 一句话用途、真实界面图、平台下载入口；用真实样本展示输入与 Markdown 结果
2. 三步流程：连接服务 → 加入文件 → 预览和导出；说明邀请或登录条件
3. 支持范围：格式、引擎条件、文件/配额限制、当前不支持事项
4. 批量、结果对比、历史、导出包等已验证功能，避免泛泛 AI 口号
5. 文件流向与保留政策；链接到更完整的说明
6. 全平台下载、版本与架构、变更记录、安装帮助、问题反馈

不要复制竞品标识、图标、文案或独特视觉设计；学习的是信息层级、反馈语义与失败恢复方式。对转化率、用户偏好、节约时间和商业价值暂不作量化结论。

## 下一轮验证的最小样本集

建议维护可公开使用的测试文件：简单 DOCX、含图表 DOCX、普通文本 PDF、扫描式 PDF、表格文件、演示文稿、损坏文件、零字节、错误扩展名、同名不同内容、中文长文件名、包含危险 HTML/链接的样本。每次发布记录输入 hash、引擎版本、配置、期望警告和导出校验。

人工走查四条旅程：首次用户连错服务器；批量中一项失败；长任务中关闭并重开客户端；完整 ZIP 导出后离开本应用使用。验证这些旅程再决定是否加入更复杂的引擎切换、命令面板或自动处理规则。

## 尚需项目实测确认

后端是否提供能力接口、状态机、任务取消与幂等提交；重试的扣额方式；任务/源文件/结果各自保留策略；引擎版本是否捕获；预览资源隔离；实际可分发平台与架构。上述建议中的依赖不能用界面文案伪装为已经实现。
