# 多用户 MVP：发布前验收清单

本清单是后续工作，不表示下面的部署操作已执行或已获授权。

## 当前实现

- 邀请注册、哈希密码、Cookie 会话、CSRF、登录限速
- 按用户隔离的持久化文件与任务、可恢复队列、限并发、配额和存储预算
- 每项下载/ZIP/预览/重试/删除都做对象级访问校验
- 默认 24 小时的文件访问有效期和运行期清理；显式删除移除文件及历史
- 最小邀请与用户额度管理；管理员不获得其他人的文档读取权
- 上游转换器兼容；本地静态前端；无 AI、支付、邮件发送或公共部署

## 部署必须另行确认

1. 选定域名、主机、运行身份和费用；确认服务对象与数据处理地区
2. 配置 HTTPS、Host/Origin 策略和 Secure Cookie；仅信任受控代理的真实来源信息
3. 保持应用与解析器低权限，给每个解析任务独立文件可见范围，隔离数据库/会话与其他用户文档；使用容器/VM 的网络与资源边界，不能只依靠 Python socket 拦截
4. 为入口设置全局速率、并发、请求体和上传耗时限制；建立磁盘余量、失败率、清理失败和队列积压告警
5. 决定数据库/文件备份、加密、保留及安全删除方式；备份内的数据是否也受 24 小时承诺约束，必须明确说明
6. 明确单实例 SQLite 的容量边界；要扩容需改用集中式数据库/队列和租约机制，不能直接增加 Uvicorn workers
7. 选择账号恢复方式并设计管理员恢复流程；目前没有密码找回或网络端的管理员初始化接口
8. 为所有 CI Python job 设置 `ORT_DISABLE_TELEMETRY=1`，并在获授权后增加 Web 检查；当前凭证没有 workflow 权限，开发提交仍跳过远程 CI
9. 用实际浏览器验证注册、登录、多标签账号切换、上传、轮询、过期、重试、下载、ZIP、退出和管理员操作；分别检查桌面/手机布局、键盘操作、屏幕阅读器及失败恢复
10. 做并发上传、压缩炸弹、慢请求、磁盘满、异常重启和数据清理演练；审查依赖漏洞和更新策略
11. 用户验收并明确批准后，才将候选版本从 dev 合并 main、配置正式账号并部署

## 已知边界

- 每个解析子进程有时间和资源限制，但不是完整 OS 沙箱；原生依赖仍需运行环境防护
- Unix/Linux 的部分防护不适用于 Windows/macOS，跨平台演练不可省略
- 清理线程只在服务运行时工作，停机期间文件可能超过物理保留时限，重启先清理；需要严格全天候删除保证时，应设计独立、受控的清理设施
- 过期文件禁止 API 访问；自然过期记录元数据可再保留 30 天，主动删除会移除记录
- 本地开发默认 HTTP Cookie 没有 Secure 标记，公网 HTTPS 场景必须开启
- 测试记录必须区分本地自动检查、模拟 DOM、真实浏览器、远程 CI 与生产验收，不互相替代
