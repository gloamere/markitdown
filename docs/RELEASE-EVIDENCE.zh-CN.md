# 版本绑定的桌面构建与下载证据

这是《产品设计与开发优化》第 6 页第一项 P0 的工程实现，不是正式发布。
后续依次核实能力/文件生命周期、固定样本导出交付，再做键盘与可访问性验收。
原有 main、v1.0.0、生产服务、Apple 账号和公证流程不在本轮修改范围。

## 要解决的实际缺口

旧下载接口只检查 SHA256 字符串格式和文件大小，没有验证实际字节；同大小的错误文件
可能带着另一文件的校验和被展示。平台/版本与文件名也没有严格对应。
安装包使用相同开发版本号时，不能仅凭文件名推断它来自最新源码或沿用旧签名验收。

## 下载信息的规则

- 元数据中的平台、版本、扩展名必须与实际文件名完全一致
- 文件必须为非空、非符号链接的普通文件，最大 1 GiB；清单读取最多 64 KiB
- 实际 SHA256 与声明不符，不展示该项；同大小替换、文件变更与非普通文件均拒绝
- POSIX 按设备、inode、大小、mtime 和 ctime 缓存最多 16 项摘要，并串行计算缓存缺失
- Windows ctime 是创建时间，不能可靠证明内容未变，因此读取当前字节重新核验
- 文件处理或认证的安全边界不变；这只影响介绍页的安装包信息

这是读取时的完整性核验，不是签名认证，也不是任意可写目录的不可变托管保证。
本地下载目录由服务运营者管理；正式分发仍需独立的签名、版本化托管和运营安排。

## 构建证据

桌面 CI 改用 `build:evidence:mac` / `build:evidence:win`，既有的语法、策略、连接、
Mac 独立服务及打包应用验证步骤继续运行。最后通过 `evidence:finalize` 生成每个安装包
对应的 `原文件名.build-evidence.json`，随已有 Actions 工件保存。

记录包括：

- 实际干净工作树的完整 commit/tree、GitHub run/attempt/job 身份（本地构建明确标记 local）
- 桌面版本、源码声明的服务/core 版本、锁定工具版本与实际执行的 Electron/Node/Chromium 版本
- 所有受检查的 app.asar 源码资源和安装包的真实大小、SHA256、平台与架构
- 实际安装包载荷与检查过的 assembled app 是否一致；具体覆盖哪些文件明确列出
- 未运行的安装/保存/覆盖人工路径，以及未验证的签名、公证、Gatekeeper 和发布状态

PR 工作流可能检出 GitHub 的合并提交；证据写入实际检出的提交，不能把它改写成推测的
`dev` 头。最终复验必须核对确切 commit 与对应工件，而非只看相同的版本字符串。

服务端转换引擎并未打包在桌面客户端里。源码声明的服务/core 版本不等于远程服务
真正执行的版本；报告对此使用 `not_measured`，不能将其写成已执行版本。
现有原生服务/界面验收仍有自己的结果；此工具不猜测它们成功。

报告是内容受限的构建观察记录，不是密码学证明或第三方认证。不会收集环境变量全集、
密码、凭据、源文档或私人路径，也不会执行签名、证书导出、Apple 登录、公证或发布。

## 将真实工件加入本地官网

```sh
.venv/bin/python scripts/stage-desktop-downloads.py \
  --mac /path/MarkItDown-1.1.0-dev.1-mac-arm64-unsigned.dmg \
  --mac-evidence /path/MarkItDown-1.1.0-dev.1-mac-arm64-unsigned.dmg.build-evidence.json
```

Windows 使用 `--windows` 与 `--windows-evidence`。可同时指定两个平台。
证据必须与安装包名称、版本、平台、架构、大小、哈希及干净源码身份匹配；错配时不替换旧清单。
先验证所有输入，再复制到临时文件核对，最后原子替换，避免展示半写入的安装包。

可省略旧构建的证据，但不会自动填入当前 HEAD 冒充来源。官网显示“未提供提交记录”。
如果证据存在，公开信息只保留受验证的 source_commit；不会将整个原始报告复制到官网。
缺少有效安装包仍显示暂未提供。上述操作只是本地文件准备，不上传、不发布、不部署。

## 验收边界与待办

自动化覆盖同大小篡改、版本/平台错配、清单/文件符号链接、目录与命名管道、未知来源、
证据与工件错配、复制失败、干净源码/打包资源及运行时一致性。
真实 DMG/NSIS 载荷检查需要对应原生 CI 运行，不能以 Linux 合成测试代替。

正式分发之前，Mac 与 Windows 仍应分别记录安装、首次启动、连接、保存、取消保存与
同名覆盖。手动保存对话框、Windows 人工安装、签名/公证仍是独立门槛，不会自动标为通过。
目前没有必要为此新增转换引擎、OCR、图片归档、通知权限或自动更新。
