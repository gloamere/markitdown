## 决策依据

[竞品资料与引用](COMPETITIVE-PATTERNS.zh-CN.md) 来自官方公开文档，不是竞品实测、
用户研究或市场结论。以下以代码审计为准，区分现状、此次实现及后续提议。

- LocalSend 的清晰文件流向值得借鉴，但本项目是 C/S：文件上传至所连接服务，
  不能沿用其“本地传输”隐私承诺。来源：https://localsend.org/
- CloudConvert 的任务/重试语义用于检查中断恢复；本项目保留同一 job 下的 attempt，
  不机械改成其新 task ID 设计。来源：https://cloudconvert.com/docs/api-reference/tasks
- HandBrake 的唯一输出名原则用于检查导出防覆盖；不重复开发已有 ZIP 命名。
  来源：https://handbrake.fr/docs/en/latest/advanced/queue.html
- Obsidian 的普通 Markdown 可迁移理念用于说明导出边界，不暗示本项目已有图片包。
  来源：https://obsidian.md/help/attachments

## 第一阶段：处理地址可见（已实现）

问题：连接页说明 C/S，但进入工作区后只显示泛化的“已连接服务”，没有实际地址。
桌面页标题还可被远程 HTML 改写，用户难以持续判断当前服务。

调整：

1. 工作区登录前后始终显示当前页面真实 origin，包含协议与端口，来源不是 API 文案
2. 地址位于主内容区，窄屏不会随侧栏隐藏；长地址允许换行，不自动打开链接
3. 桌面系统窗口标题固定显示用户实际选择的服务 origin，远程页面不能改写此标题
4. 状态文字改为“服务配置已读取”，不把一次配置读取包装成持续可达、已登录或能力保证

不根据 localhost 推断“全部离线”；不增加遥测、权限、preload 或远程 Node 桥。

验收：真实 origin 优先于服务自报名称；登录/退出保持地址；IPv6/端口正确；
远程 document.title 不能替换原生标题；320/390/1440 宽度无溢出。

## 后续有界阶段

### 第二阶段：中断恢复边界（已实现）

已复现缺口：首次上传被接收但响应丢失后，安全重试收到 429 会清除原幂等键，
之后正常提交可能重复入队/计次。429 可以发生在服务查询幂等记录之前；
收到一次拒绝不能证明此前请求未被接收。新增回归在修复前确实失败。

已修复：不确定上传保留原 key、文件对象和引擎，跨越 400/403/409/429/5xx 拒绝，
直到成功对账或用户明确放弃。第一次明确拒绝仍允许修改文件后重新提交。
任务 retry 同样保留其键，直到确认成功、尝试数变化或会话清空。
401/跨账户响应仍先清空会话；退出后迟到的拒绝不能重新显示旧文件。

验收：新增 4 组 DOM 场景（含状态矩阵），65 组全部通过；同一文件的三次请求
使用相同 key/对象/引擎，模拟服务只入队和扣额一次；新尝试能轮换键。
已有部分成功、显式放弃与退出隔离回归继续通过。
没有更改后端额度、身份校验，也没有增加浏览器持久化文档。

### 第三阶段：较晚响应尊重新的操作（已实现）

独立复核复现两处细节问题：取消/重试 A 的响应较晚到达时，会把已经切到 B 的
阅读区拉回 A；复制 A 的权限请求稍后失败时，会切换并选中当前 B 的源码。
这是同一账户内的对象/焦点错误，不据此声称发现跨账户泄漏。

调整：取消/重试继续更新 A 的状态，但不覆盖其后选择的 B 或中断 B 的结果读取。
复制的迟到反馈与降级仅在原上下文仍有效时执行；选文件、切换页面/阅读模式、
隐藏邀请码、发起新复制或退出都会使旧反馈失效。不会“撤回”系统已完成的复制。

新增回归包括取消和重试两类、B 已加载/仍在加载两类、剪贴板成功/失败、
导航离开再返回、阅读模式选择、邀请码隐藏；69 组 DOM 场景全部通过。
原有正常复制回退、选择/退出隐私和键盘焦点场景继续通过。

### 第四阶段：可移植导出（已实现）

实际复现：160 个中文字符的下载建议名为 483 个 UTF-8 字节，在云端临时目录
保存报 ENAMETOOLONG；旧桌面截断还会丢掉超长 ASCII 文件名的 .md 扩展名。
CON.md 等名违反 Windows 保留名规则。

调整：下载建议名限制为 180 UTF-8 字节，完整保留输出扩展名，不切断 Unicode 字符；
Windows 设备保留名加 document- 前缀。桌面建议名同时清理尾点/空格与方向控制符。
ZIP 沿用任务 ID/序号区分条目，加入此后缀后仍低于 200 字节；不改变源文件展示名、
原文内容、任务 ID、源哈希、计次或文件保留策略。

验收：首批 7 个新增服务用例在修复前全部失败；独立复核后补充 5 个设备别名/空格用例。
实际保存、ZIP 解压、
长中文/emoji、保留名、截断后同名的不同任务和原始记录保持均有回归。
桌面另有 UTF-8/扩展名、设备保留名和当前平台实际创建文件测试。
这是安全的建议文件名，不承诺任意用户选择的完整路径都可写；
桌面保存/覆盖仍由系统对话框处理，网页下载由浏览器策略决定。

技术来源：[Windows 文件命名规则](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)、
[Electron DownloadItem](https://www.electronjs.org/docs/latest/api/download-item/)。
不增加“完整归档”或图片资产等尚未实现的宣传。
